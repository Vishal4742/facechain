# Phase 6 — SAS attestation sidecar

Date: 2026-09-05

## Built
- `chain-ts/sas.ts` — ESM TypeScript sidecar run by Node 24 type stripping (`node chain-ts/sas.ts`): one JSON command on stdin, one JSON result on stdout, `{"error": "..."}` + exit 1 on failure. Commands: `setup` (Credential `FACECHAIN`, authority = registry wallet, signers = [wallet]; Schema `FaceMatchV1` v1, layout `[12,12,12,3]` = String,String,String,U64, fields `bundle_hash, cid, post_url, similarity_bps`; idempotent — existing PDAs are not resent, an existing schema is checked for the same layout/fields), `attest` (nonce = the 32 bytes of the bundle hash decoded as an address, PDA derived, no resend when it exists, `expiry` 0) and `fetch` (derive → `fetchMaybeAttestation` → `deserializeAttestationData`). Transactions are built with kit (`pipe`, `createTransactionMessage`, `setTransactionMessageFeePayerSigner`, `setTransactionMessageLifetimeUsingBlockhash`, `appendTransactionMessageInstructions`, `signTransactionMessageWithSigners`), sent with `sendTransactionWithoutConfirmingFactory` and confirmed by polling `getSignatureStatuses` (no websocket dependency). The keypair bytes never reach a log or an error message.
- `chain-ts/package.json` pins `sas-lib@1.0.10` + `@solana/kit@5.5.1`: sas-lib 1.0.10 (latest stable, 2025-11-19) lists `@solana/kit ^5.0.0` as a regular dependency, so kit 5.5.1 dedupes to one copy; `sas-lib@2.0.0-beta.1` (2026-09-01) wants kit ^7 and is four days old, so it stays an upgrade path (beta.1 + kit 7.1.1). `tsconfig.json` uses `erasableSyntaxOnly` + `verbatimModuleSyntax`, so `npx tsc --noEmit -p chain-ts` proves the file runs under Node's type stripping.
- `facechain/chain/sas.py` — `call_sidecar` (subprocess, JSON in/out, `SasError` on non-zero exit or an `error` key, `npm ci` hint on a missing package), `setup_sas` (writes `SAS_CREDENTIAL` / `SAS_SCHEMA` into `.env`, creating it from `.env.example`, never overwriting a set key), `attest`, `fetch_attestation`, `check_attestation` + `effective_hash`: `verify` derives the PDA from the hash of the evidence as it is on disk — when the media no longer matches the bundle, the bundle is re-hashed with the actual media digest, which yields a PDA nobody ever attested.
- CLI: `facechain setup-sas`; `facechain attest --run DIR` (attest an already anchored run, no new memo); `--sas` on `anchor` and `run` (attests right after the memo and records `sas` in `receipt.json`; refuses to start when SAS is not configured, so no memo is ever sent without its attestation); `verify` shows the attestation rows whenever SAS is configured. `python -m facechain.cli …` now works (main guard) — needed in worktrees, where the `facechain` console script resolves to the main checkout.
- Tests: `tests/test_sas.py` — 22 unit tests with the subprocess / sidecar mocked (call_sidecar, `.env` writing, payloads, comparison, tampered-hash derivation, report rendering, `anchor --sas`, `attest`, `setup-sas`) + 1 `network` test (`FACECHAIN_LIVE=1`).

## Decisions
- sas-lib API (all names confirmed from `node_modules/sas-lib/dist/src/**/*.d.ts`): `deriveCredentialPda`, `deriveSchemaPda`, `deriveAttestationPda`, `getCreateCredentialInstruction`, `getCreateSchemaInstruction`, `getCreateAttestationInstruction`, `fetchMaybeCredential`, `fetchMaybeSchema`, `fetchMaybeAttestation`, `serializeAttestationData`, `deserializeAttestationData`, `SOLANA_ATTESTATION_SERVICE_PROGRAM_ADDRESS`; kit: `createKeyPairSignerFromBytes` on the 64-byte `id.json` array, `getAddressDecoder().decode(bytes)` for the nonce. sas-lib 1.0.10 ships CommonJS; named ESM imports work through Node's cjs-module-lexer.
- The schema has four fields (`bundle_hash`, `cid`, `post_url`, `similarity_bps`) instead of the seven sketched in `docs/ARCHITECTURE.md`: everything else is inside the bundle that the hash commits to, and the memo already carries the media hash.
- Verdict rule: an attestation that exists but disagrees with the bundle or the registry → TAMPERED; an absent attestation never changes the memo verdict (runs anchored before Phase 6 stay VERIFIED and simply show `attestation ABSENT`).
- Memo and attestation stay two transactions: the memo is pure Python (unchanged), the attestation goes through the sidecar; `@solana-program/memo` is never imported.
- Confirmation by polling `getSignatureStatuses` rather than `sendAndConfirmTransactionFactory`, which needs a websocket subscription to the public devnet endpoint.
